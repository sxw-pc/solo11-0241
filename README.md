# 节点维护交接所

离线节点维护控制面。三个独立入口：维护许可、驱逐迁移、复役关单。SQLite 保存节点身份、服务保护预算、工单、负载、卷写权、健康探针和归属案。

运行：`python -m clouddrain.cli all fixtures/demo.json --db demo.sqlite`。测试：`python -m unittest discover -s tests -v`。仅依赖 Python 标准库；首次打开数据库自动建表。

许可时按服务分别保护最大不可用副本数，紧急豁免需要两种不同角色及不同批准者。驱逐先保持源端，再验目标身份、容量和故障域；卷写权只有源端解绑且目标写屏障就绪后转移。关单需清点登记残留和未登记游离负载，并要求本节点代际的磁盘、网络、运行时探针都通过。

## 离线分叉审计

本地 `verify_replay` 只证明本机 `audit_log` 能还原本机业务表，**不能**证明它是唯一历史。两台从同一备份恢复的控制台可以各自自洽，却把同一工单记到不同物理节点（例如 alpha 记 uid `ua`、beta 记 `ub`）。报告因此按以下类别出具：

- `published`：范围内见证根可由逐事件内容与业务表状态复算，无已保留冲突。仍明确标注仅限本分支、跨站唯一性未证。
- `disputed`：存在保留的根/物理身份冲突。并列列出所有根，明确不声称工单已对某物理节点生效。
- `certified`：客户授权裁决人依据现场证据（两台控制台、节点实物、独立见证）作出裁决，报告含被否决分支及不可证事实。
- `hold`：无法诚实出具（无证据或本地重放已损坏）。

见证根 `root` 提交到前缀事件链和该前缀还原出的业务表状态；同一序号不同内容的根无法相等。`audit_chain` 密封链与业务事件一一对应，断电/恢复重用序号覆盖另一分支会报 `history_rewritten`。见证原件、`audit_evidence` 内容寻址证据、已发布报告与裁决均只增不改；签名撤销只追加风险说明，重复见证按唯一见证者计。两种交付都保留 alpha、beta 原件与旧报告。


后续边界：跨机架批量维护排程、异地灾备接管、热升级阶段协调、硬件故障预测隔离、租户驱逐补偿、维护审批职责分离、运行时版本兼容、网络拓扑迁移约束。当前版本不实现。
